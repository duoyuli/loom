# 知识库

这是一个由 Agent 协助维护的本地 Markdown 知识库，它的目标不是把资料临时丢给模型再现场回答，而是把知识持续沉淀进一个可检索、可链接、可复用的系统内。

这里的基本分工是：
- 人负责选择资料、判断研究方向、提出问题。
- Agent 负责摄入资料、整理页面、建立链接、纠错回写和维护索引。

仓库的具体工作约束见 [`AGENTS.md`](./AGENTS.md)。`README.md` 负责说明这个仓库是什么、怎么用；`AGENTS.md` 负责约束 Agent 应该怎么做。

```text
│   ├── concepts/
│   └── analyses/
└── writing/

```

## 三层分工

- `raw/`：原始资料层，保存原文、摘录、截图、附件和链接指针，默认不可改写。
- `wiki/`：知识沉淀层，是日常查询、复用和继续研究的主界面。
- `writing/`：写作输出层，承接基于 wiki 的专题草稿与定稿文章。

## 目录说明

- `raw/sources/`：原始资料文件，或指向外部资料的指针笔记。
- `raw/assets/`：原始资料引用的图片、附件等资源。
- `wiki/index.md`：wiki 总目录，进入知识库时默认先读这里。
- `wiki/log.md`：按时间追加的操作日志，记录摄入、纠错、巡检和重要分析沉淀。
- `wiki/overview.md`：当前知识库的高层概览。
- `wiki/sources/`：每份资料对应一页，记录摘要、关键主张、相关性和线索。
- `wiki/entities/`：人物、公司、产品、项目、组织、地点等稳定对象。
- `wiki/concepts/`：主题、方法、框架、争议和重复出现的概念。
- `wiki/analyses/`：值得长期保留的时间线、对比、综合判断和备忘。
- `writing/`：专题文章；已发布文章默认视为按日期冻结的快照。
- `writing/index.md`：文章入口页。

## 这个库怎么工作

这个仓库的默认路径不是“问一次，答一次”，而是：

1. 先把资料放进 `raw/sources/`。
2. 让 Agent 把资料整理进 `wiki/sources/`。
3. 再更新受影响的实体页、概念页、分析页和链接关系。
4. 如果发生了实质更新，同步维护 `wiki/index.md` 和 `wiki/log.md`。
5. 后续回答问题、继续研究、写文章时，都优先复用 wiki，而不是重新翻原始资料。

换句话说，知识优先沉淀到 `wiki/`，回答和写作建立在 wiki 之上。

## Agent 的核心约束

根据 [`AGENTS.md`](./AGENTS.md)，这个仓库默认遵循这些原则：

- `raw/` 下的原始资料不可变。
- 优先更新已有页面，不优先新建语义重复页。
- 优先维护许多小页和清晰链接，而不是单个大页。
- 必须保留不确定性、冲突点和证据边界。
- 新旧结论冲突时，优先更新原页面并记录冲突。
- 只有有长期复用价值的内容，才沉淀到 `wiki/analyses/` 或 `writing/`。

## 常见任务

### 1. 摄入资料

适合在这些情况触发：

- 新增了一份文章、笔记、PDF、访谈或网页摘录。
- 某份资料里的判断值得进入长期知识库。

最小完成标准通常是：

- 有对应的 `wiki/sources/` 页面。
- 受影响的实体页、概念页或分析页已经更新。
- `wiki/index.md` 和 `wiki/log.md` 已同步更新。

### 2. 基于知识库回答问题

适合在这些情况触发：

- 想问“这个主题目前库里怎么说”。
- 想让 Agent 基于已有 wiki 做综合回答。

默认流程是先读 `wiki/index.md`，再读相关页面；只有确实值得长期保留的回答，才回写到 `wiki/analyses/`。

### 3. 深度研究

适合在这些情况触发：

- 某个实体或概念反复出现，值得系统整理。
- 需要长期保留的时间线、比较或综合判断。

深度研究默认优先复用已有页面；只有现有 wiki 不足时，才新建分析页。分析页优先采用 `timeline`、`comparison`、`synthesis` 这三类形态。

### 4. 专题写作

`writing/` 不是原始笔记堆放区，而是基于 wiki 的输出层。写文章前，如果证据还不够，应先补 wiki，再写草稿。文章中的关键判断应能回溯到支撑它的 wiki 页面。


## Codex 自动化巡检

你是 Loom 个人知识库的定时巡检 Agent，请在当前仓库中执行一轮增量巡检，并尽量在无人值守场景下安全完成。

开始前：
1. 读取并遵守当前目录及相关子目录中的全部 AGENTS.md 规则。
2. 以 wiki/index.md 为默认入口；涉及来源、引用、资料映射时，同时读取 wiki/sources/index.md。
3. 不得重写、移动或删除 raw/ 下的原始资料。

巡检重点：
- 未摄取的材料
- 内容冲突或相互矛盾的说法
- 孤页、断链、错误链接和不可达页面
- 缺少来源、来源不明或来源映射错误
- 重复概念、重复页面或 canonical 路径不一致
- wiki 页面与 wiki/sources 的对应关系问题
- 重要主题下明显缺失的研究空白
- 影响检索、导航、索引质量的问题

处理原则：
1. 优先修复可检索性、来源映射和链接关系。
2. 只更新真正受影响的最小页面集合。
3. 不做大规模改写、风格统一或无关整理。
4. 对无法可靠判断的事实冲突，不要猜测修正；应保留现有内容，并在合适位置标记为待核查。
5. 若对 wiki/ 做了任何实质变更，必须同步更新 wiki/index.md 和 wiki/log.md，记录本次巡检的时间、范围和摘要。
6. 若没有明确收益，不要为了制造变更而编辑文件。

完成后：
1. 检查 git 工作区，工作区中有未提交内容，进行 git commit 和 push，遇到冲突自行处理
