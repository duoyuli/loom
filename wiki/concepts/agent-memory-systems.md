Agent 记忆系统指的是 Agent 在当前上下文窗口之外，用来持续保存、检索和重用状态的一整套机制。它不是单个"记忆库"或单次向量检索，而是同时包含写入规则、存储分层、检索策略、整理与遗忘机制、治理层和跨时间演化表示的外部状态层。Memory 的核心不是"把过去留下来"，而是**治理过去如何进入现在**。

## 定义

### 四类记忆（CoALA 框架）

CoALA（Cognitive Architectures for Language Agents）借用认知科学的分类，把 Agent 记忆系统拆成四种不同的时间残留物：

- **工作记忆**：Agent 当下可直接参与推理的上下文。所有外部记忆最终必须通过这个瓶颈才能影响当次行动。窗口再大，能触碰到的仍只是被成功送入的那一小块。
- **情景记忆**：带时间属性的经历记录——一次对话、一系列工具调用、一场失败的尝试。Generative Agents 在这个方向上的核心贡献是：用"近因性 × 重要性 × 相关性"三重加权检索，并在累积重要性达到阈值时触发反思，把离散经历提炼为更高阶的理解，从而催生涌现行为。
- **语义记忆**：从大量经历中蒸馏出的稳定知识：用户偏好、实体关系、长期约束。比情景记忆更紧凑，但代价是失去原始语境。HippoRAG 用知识图谱索引和图传播机制模拟这种从经历到结构化知识的迁移。
- **程序性记忆**：反复验证后内化为稳定行动模式的操作结构——Skills、SOP、可复用操作套路。是最容易被低估的一层。

这四类记忆的意义不是提供名字标签，而是回答"经历能否被转化，转化是否还能回溯，回溯之后又能否重新进入行动"。

### RAG 不是 Memory

这是当前最需要澄清的混淆。

- **RAG**：把外部知识源中相关内容检索出来注入当前上下文。解决的是"模型不知道，但资料库里有"的问题；主要是一次性的"读"。
- **Memory**：把互动中形成的偏好、事实变化、错误教训、长期约束，组织为能持续影响未来行为的状态；必须覆盖写入、更新、替代、失效、删除的完整生命周期。

把 Memory 误解为"更聪明的检索"，会导致架构做偏：以为问题在召回率，实际上问题在连续性；以为把历史搜回来就够了，实际上系统还必须知道哪些该保留、哪些该更新、哪些已经失效。RAG 和 Memory 的差别，不是实现技巧的差别，而是**一个系统有没有开始拥有历史**的差别。

## 纵向脉络

- 最朴素的做法，是把全部历史继续塞在上下文窗口里；token 成本和上下文衰减会很快成为瓶颈。大上下文只是把"尽量存原始"路线推到极致，它不是终点。
- 再往前一步，是把长期状态外移到 Skills、会话日志、`MEMORY.md` 或其他持久层，并按需回填到当前上下文。
- MemGPT 的操作系统隐喻重新组织了这个问题：把上下文窗口视为 RAM，外部存储视为磁盘，Memory 的问题就变成"如何在有限工作区和外部长时存储之间建立有效调度"，而不只是"怎么检索"。
- Mem0 等工程实践把问题进一步具体化：`ADD-only` 写入保留状态变化，agent-generated facts 入库，实体链接与多信号检索融合，说明记忆系统质量越来越依赖写入层与检索层一起设计。
- OpenClaw 的实现样本则把另一条工程路线补了出来：长期核心层 `MEMORY.md` 固定进入主会话，日记层 `memory/YYYY-MM-DD.md` 通过 `flush -> chunk -> retrieval -> line read` 的链路按需召回，并让每日记忆随时间衰减。
- Hermes / OpenClaw 的比较进一步说明，记忆系统的关键差异往往先发生在“写入触发时机、跨不跨项目、默认读什么”这几件事上，而不是某个向量库或后端名字。
- 当前边界：情景记忆的长跨度时间推理和多 session 结构仍是明显难点；"事实和实体都能找回来"还不等于"系统理解了事件如何演化"。

## Memory 生命周期

Memory 不是一个存储动作，而是一条生命周期管线，每个阶段都会造成信息损失、语义偏移和选择性偏见。

### 写入

- **提取候选**：从对话、工具调用、环境观察中识别可能值得长期保留的内容。
- **写入门控**：短暂寒暄、瞬时状态、低价值噪声不应无差别进入记忆。很多系统的败局不是读错，而是**写脏**。
- **元数据标注**：没有类型、来源、时间、置信度的记忆，只是文本碎片，无法进入可治理系统。

### 整理

核心操作：合并去重、冲突调解、版本替换、衰减归档、标记失效。真正成熟的系统把记忆看成**有生命周期的状态对象**，而不是永远平铺、永不失效的文本条目。Memory 真正难的地方从来不是"留下来"，而是让旧版本以正确的方式退场。

### 读取

成熟的读取不是一次向量搜索，而是一条管线：混合召回、重排序、过滤、预算裁剪、上下文组装。系统不是在"还原过去"，而是在"为当前任务重构一个可行动的过去版本"。

## "破电话"效应：原始 vs 派生

几乎所有 Memory 系统最终都会碰到一个根本矛盾：

- **原始材料（Raw）**：忠实于事实，但太散、太碎、太贵，缺乏可操作意义。
- **派生材料（Derived）**：摘要、画像、偏好标签、关系图谱，可索引、可注入、可决策，但已经经过解释和压缩，会随着反复改写而系统性漂移——先丢语气，再丢语境，再丢边界条件和例外项。

更危险的是派生材料会继续喂养新的派生材料。**记不住最多是缺失；记错了还以为自己记得很清楚，才是真正的污染。**

解决方案不是二选一，而是同时持有两者，并在两者之间建立**可回溯、可校验、可重构的路径**：如果没有证据层，系统会漂；如果没有派生层，系统会钝。

## 遗忘的重要性

删除不是一键清空。删掉原始消息，不等于删掉摘要；删掉摘要，不等于删掉由它提取的偏好。Forget 不是 Delete，而更像一场**谱系清算**——追溯这条信息去过哪里、变成过什么、影响过哪些派生物。

好的 Memory 不是"永不遗忘"，而是必须拥有高质量遗忘能力：让重要的东西留下，让失效的东西退场，让历史可以被审计，但不再统治现在。成熟的遗忘是带有版本意识、时间意识和依赖传播意识的退场机制——它管理的不是消失，而是**失效之后仍然可追溯、但不再继续支配当前行为**。

## Skills：程序性记忆的外化

Skills 是程序性记忆的外化形式，代表了记忆从"保存过去"走向"塑造未来行为"的成熟产物。

- 经验最开始只是"发生过"；
- 被反思之后变成"总结过"（情景 → 语义）；
- 被反复验证之后才变成"会做了"（语义 → 程序性）。

Reflexion、ExpeL、ReMe 等工作都在回答同一个问题：经历如何不只是被保存，而是被提炼成下一次行动时可直接调用的能力。关键发现之一是：高质量的程序性记忆不只提升成功率，在某些场景下甚至可以部分替代模型规模本身的不足。**Memory 的终点不是档案，而是能力。**

## 五种架构哲学

| 哲学 | 重点 | 优势 | 风险 |
|---|---|---|---|
| 文件驱动 | 可见、可编辑、可审计的外部文本 | 透明性、可干预性 | 不天然擅长自动演化 |
| 图谱驱动 | 实体、关系、状态变化和时间有效性 | 适合"同一对象不同时期状态不同" | 实现复杂度高 |
| 混合存储驱动 | 向量+图+KV 分工承载不同性质记忆 | 各结构发挥所长 | 工程集成成本高 |
| 策略学习驱动 | 学习"何时记、记什么、何时忘、如何改写" | 手工启发式规则被可学习策略替代 | 学错策略难以发现 |
| 技能蒸馏驱动 | 把记忆终点设为可复用能力 | 上限最高 | 蒸馏出错则高效率地重复错误 |

架构哲学的本质不是技术选型，而是**你认为什么东西才配被叫做记忆**。

## 治理层

治理层处理的不是"怎么把信息拿进来"，而是：这条记忆从哪来？是原话、摘要还是推断？新旧信息冲突时谁覆盖谁？用户要求删除时哪些派生物要连带失效？哪些敏感信息不能跨场景带出？

治理层真正管理的是：**来源、权限、生命周期、置信度、影响范围和可撤销性**。没有治理层的 Memory，很容易从"连续性来源"变成"污染源"——混淆原话和推断、混淆历史事实和当前状态、混淆私人上下文和可跨任务带出的长期知识。

这也是为什么 Memory 更像操作系统而不是数据库：数据库关心数据在不在；操作系统关心资源如何被调度、隔离、继承、回收、审计和控制。

## 多 Agent 记忆共享

多 Agent 协作时，记忆问题从"记住什么"升级为：谁能看到什么？谁能修改什么？谁知道谁知道什么？一个 Agent 的误记忆会不会污染整个协作网络？

真正难的不是共享，而是**在共享中维持边界、追溯和一致性**：
- 边界不清 → 记忆互相污染；
- 追溯不清 → 错误失去责任主体；
- 一致性崩坏 → 共享历史变成彼此冲突的叙事碎片。

## 新增视角：写入触发与作用域本身就是记忆设计

- OpenClaw 的资料把作用域拆得很清楚：`MEMORY.md` 是持续暴露的长期层，日记层是只在需要时搜索的细节层；写入既可以显式触发，也可以在压缩或会话结束时被动 `flush`。
- Hermes / OpenClaw / Claude Code 的比较则说明，记忆系统首先回答的可能不是“用什么检索”，而是“这是记项目、记用户，还是记整个长期关系”。
- 当作用域不同，后续的治理和风险也会完全不同：项目隔离更安全但关系连续性弱；跨项目长期记忆更像个人档案，但更需要权限边界和遗忘机制。
- 这也解释了为什么 Memory 不能只被理解成一个技术模块，它同时还是产品边界和协作边界的设计。

## 新增视角：先分清 Memory 和它的邻居

- `Agent Memory 架构本质` 把边界进一步讲清：`State` 处理 session 内短期运行态，`Policy` 处理权限和安全边界，`Profile` 只是用户模型的低维快照。
- 这条边界很重要，因为它防止系统把“任何可持久化的东西”都塞进 Memory 概念里，最后失去治理抓手。
- 同一篇资料还提醒，蒸馏、摘要和 reflection 都只是 memory pipeline 中的管理动作；如果没有后续的冲突修正、衰减和回溯，它们更像归档而不是记忆。

## 新增视角：记忆需要对象模型和状态字段

- 新补资料提出了四类建模对象：用户模型、任务模型、世界模型、自我模型。这比“只记用户偏好”更接近真实 Agent 连续理解的对象范围。
- 它还把单条记忆压成至少六个维度：内容、类型、置信度、来源、作用域、时间与衰减。另一个实现性更强的来源页，则把这些治理需求落成 `confidence / decay_score / status / contradicted_by / expires_at` 一类生命周期字段。
- 这两条线一起说明：Memory 的最小单位不应只是文本块，而应是可冲突处理、可排序、可退场的状态对象。

## 新增视角：生命周期维护独立于检索

- `停止将 AI 记忆视为搜索问题` 提供了一个很清楚的工程提醒：即使检索已经能把相关内容找回来，系统仍可能因为不会衰减、不会过期、不会检测矛盾而长期依赖过时事实。
- 这说明 Memory 的主问题不只是“如何找到”，还有“何时降权、何时归档、何时被更新替代、哪些维护动作该后台异步执行”。
- 与 Mem0 的 `ADD-only` 写入路线放在一起看，可以更清楚地区分两件事：一件是保留状态演化轨迹，另一件是让旧状态在后续决策中逐步退场；两者缺一不可。

## 新增视角：分层记忆不等于可直接信任

- 新摄入的 `The Anatomy of an Agent Harness` 又提供了一个更偏运行时的记忆样板：轻量索引常驻、详细主题文件按需加载、原始记录只在必要时搜索。
- 这条样板的价值，不只是再次证明“记忆应分层”，而是补上一条更谨慎的使用原则：Agent 对自己的记忆更适合持“提示线索”态度，而不是把回忆结果直接当成当前事实。
- 换言之，记忆系统负责提高连续性和找回率，但行动前仍应尽量回到真实环境、真实文件或真实状态做核验；否则系统只是在更高效地复用旧判断。

## 新增视角：记忆也是数据工程

- 新摄入的系统工程来源把 Agent 记忆明确拉回数据工程：Memory、storage、knowledge 和 context 都应有 schema、结构化查询、数据库、对象存储和持续更新管道。
- 这与本页的治理层判断互补：如果记忆只是共享沙箱里的文件，系统很容易在权限隔离、审计、跨用户泄漏和生命周期管理上欠账。
- Dash 案例还提供了一条实践线索：错误模式、修复方式、新建视图 schema 和示例查询都可以作为“学习记录”写回数据层；Agent 变好并不是因为模型权重变了，而是上下文数据层变好了。

## 评估

Memory 的评估不应只测"能否想起"，还要测：

- 在很长时间跨度上能否稳定找回真正相关的信息？
- 能否分辨"曾经成立"和"现在仍然成立"？
- 会不会把旧偏好、旧事实、旧约束错误带到当前场景？
- 能否处理冲突、替代、版本变化和例外条件？
- 多次摘要后是否会漂移（"破电话"效应）？
- 有没有选择性遗忘能力，而不是一味堆积？
- 当系统说"我记得"时，是在召回原始证据，还是在召回自己以前的总结？

## 横向位置

- 对 [Context Engineering](context-engineering.md) 而言，记忆系统是最重要的外部上下文来源之一；前者决定什么时候把哪些记忆装回来，后者决定系统到底保存了什么、找回了什么。
- 对 [Agent Session Management](agent-session-management.md) 而言，会话管理处理的是"当前历史该如何继续保留"，记忆系统处理的是"哪些状态应该跨会话持续存在"。
- 对 [Harness Engineering](harness-engineering.md) 而言，记忆写入策略、去重规则、回退机制、评测集和 token 预算，都属于应该被工程化和被验证的外层程序。
- 对 [信息分层设计](information-layering-design.md) 而言，摘要层、实体层、事实层和原始事件层是否拆开，会直接影响后续检索与装载质量；"破电话"效应说明派生层的每一步压缩都应有原始层可回溯。
- 对 [Agent 学习闭环](agent-learning-loop.md) 而言，Skills 的形成本质上是程序性记忆的外化，Memory 的终点与学习闭环的终点在"能力"这个词上汇合。

## 当前判断

- Memory 系统的难点不是"记住更多"，而是"在有限预算下记对、找对、保留变化过程、并让旧信息以正确方式退场"。
- 记忆边界、对象建模和生命周期字段，决定了系统后续能否治理；如果一开始只存文本，很多后处理能力根本无从展开。
- 写入路径和检索路径同等重要。写入时把状态变化覆盖掉，后面的时间推理很难补回来。
- Raw 和 Derived 必须同时持有，并维持可追溯路径；二选一会导致要么太重要么漂移。
- 遗忘不是删除，是依赖传播意识的谱系清算。
- Memory 的高级形态不是更会存，而是更会治理。
- 当前知识库的证据已覆盖治理、生命周期和实现性样本，但跨框架一手对照仍明显不足；尤其缺少 ChatGPT Memory、LangMem、NotebookLM 等不同产品边界的系统比较。
