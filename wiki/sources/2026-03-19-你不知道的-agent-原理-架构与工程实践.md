这是一篇面向工程落地的 Agent 架构综述。它最值得长期保留的判断不是某个单点实现技巧，而是：真正决定 Agent 能否稳定跑起来的，通常不是把主循环写得更复杂，也不只是换更贵的模型，而是把控制流外的上下文分层、工具接口、记忆体系、任务协议、评测追踪和安全边界一起工程化。

## 这份资料是什么

- 资料来自一篇长文摘录，作者试图把自己读过的资料、开源实现和编码实践压缩成一张 Agent 工程地图。
- 内容覆盖 `Agent Loop`、`Workflow vs Agent`、Harness、上下文工程、工具设计、记忆系统、自主度、多 Agent、评测、追踪与安全，并用 `OpenClaw` 作为落地案例收束。
- 它更像高信息密度的二手系统化综述，而不是单一论文或单一产品的官方设计文档。

## 主要观点

1. Agent 的核心循环本身很稳定，新增能力大多应叠加在循环外部，而不是把 loop 写成巨大的状态机。
2. 在代码、测试等高可验证任务里，Harness、验收标准和反馈回路，往往比单纯升级模型更决定结果是否稳定。
3. 上下文管理的关键不是“塞更多信息”，而是分层、按需加载、压缩和缓存友好；`Skills` 应作为按需知识接口，而不是常驻长提示的一部分。
4. 工具设计应面向 Agent 目标而不是底层 API，参数边界、错误结构和调用示例会直接影响工具选择正确率。
5. 记忆不该混成一个桶；工作记忆、程序性记忆、情景记忆与语义记忆需要分层存放、按需检索，并具备可回退的整合流程。
6. 长任务自主度建立在外部状态之上：进度、任务图、跨 session 恢复点和慢速 I/O 结果都应写入系统外部，而不是只留在对话上下文里。
7. 多 Agent 的前提是协议、任务图和隔离边界，不能把并行协作误当成“多开几个模型”。
8. 真正可持续的 Agent 优化必须先有评测与 Trace；没有稳定可复现的失败记录，就很难知道该改评测、环境还是 Agent 本身。

## 关键内容

### 控制流：简单 loop，复杂性外置

- 文中把 Agent Loop 压缩为“感知 -> 决策 -> 行动 -> 反馈”的重复循环，并强调多数扩展能力都应通过工具、系统提示结构或外部状态接入。
- 它同时区分了 `Workflow` 与 `Agent`：执行路径由代码预写的是 Workflow，由模型动态决策下一步的是 Agent。
- 五种常见控制模式被放到同一张地图中：`Prompt Chaining / Routing / Parallelization / Orchestrator-Workers / Evaluator-Optimizer`。

### 上下文、工具与记忆：外层程序比 loop 更关键

- 上下文部分强调 `常驻层 / 按需加载 / 运行时注入 / 记忆层 / 系统层` 的分层管理，并把 `Context Rot` 视为常见失效模式。
- 资料把 `Prompt Caching`、`Skills` 描述符设计、文件系统作为动态上下文接口等内容一起纳入 Context Engineering，而不把它缩成“写 prompt 的技巧”。
- 工具设计部分明确主张 `ACI (Agent-Computer Interface)`：工具应对应 Agent 的目标，且提供结构化错误和调用示例。
- 记忆系统被拆成四类：上下文窗口、Skills、JSONL 会话历史、`MEMORY.md`；其中整合机制必须允许回退，不能通过摘要直接覆盖原始历史。

### 自主度、多 Agent、评测与追踪：都需要外部协议

- 长任务稳定推进依赖外部进度锚点，例如 `feature-list.json`、任务状态文件和可恢复的 session 外状态。
- 多 Agent 章节的核心判断是“协议先于协作”：应先定义消息协议、任务图和 worktree 隔离，再谈并行与交叉验证。
- 评测部分区分 `task / trial / grader`、`transcript / outcome`、`agent harness / evaluation harness`，并强调要先修评测，再改 Agent。
- Trace 部分主张记录完整 prompt、消息、工具调用、结果、token 与延迟，并以事件流承接日志、UI、在线评测和人工审查等多个下游。

### OpenClaw 案例：把原则落到系统分层

- `OpenClaw` 被当成一个把前述原则拼回系统实现的案例：消息总线解耦渠道与 Agent、主循环与渠道隔离、工具按 ACI 设计、`Skills + MEMORY.md` 组成上下文与记忆层。
- 文中也强调系统提示应按层叠加，而不是塞进单文件；子 Agent 应只拿最小提示，不继承全部 Skills 和 Memory。
- 安全边界被放在功能之前：先定义禁止项、权限约束和兜底路径，再扩展能力面。

## 与知识库的相关性

这份来源和当前知识库主题高度一致。它直接补齐了此前较少展开的运行时工程面：为什么主循环不该无限膨胀、为什么上下文和工具定义是第一性问题、为什么任务状态与跨 session 恢复必须外化、为什么多 Agent 必须先有协议和隔离、以及为什么评测与 Trace 不是后补件而是前置基础设施。
