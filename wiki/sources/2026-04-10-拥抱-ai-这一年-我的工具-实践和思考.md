这是一篇基于个人实践的一手回顾，核心价值不在于某个具体工具，而在于把 AI 协作总结为一套可持续演进的工作流：先把 Agent 用起来，再用 Context、Spec 和 Harness 约束它，最后让 Agent 参与自己的学习与工作空间进化。重摄入后，这页也补上了原文后半段关于 `Jagged Intelligence`、AI Native 落差和早期采用摩擦的判断边界。

## 这份资料是什么

作者回顾了过去一年在 AI 产品、Agent 开发实践和个人工作流上的投入与变化，内容混合了工具清单、方法论演进和对 AI 时代学习方式的判断。

## 主要观点

1. AI 协作的重心已经从单次 prompt 优化，逐步转向对上下文、契约和约束体系的系统设计。
2. Agent 真正稳定可用，依赖的不只是模型能力，还依赖工程化的“缰绳”，包括规范、测试、清理和反馈回路。
3. 在知识快速过时的环境里，个人学习方式需要转向“让 Agent 采集、筛选、提炼并反哺工作流”的闭环。
4. 即使作者讨论 AI Native，当前高投入产出比的实践仍然很“过渡态”：围绕现有最强 Agent 工具、工作空间和协作习惯做增强，而不是等待理想形态一次到位。

## 关键内容

### 工具与工作空间

- 文章把 `Raycast`、`AeroSpace`、`Ghostty`、`tmux`、`Claude Code` 等工具放在同一工作流里看待，强调的是多 Agent、多终端、多机器协作时的可观察性与切换成本。
- 文中自研 `Cockpit` 用来监控跨机器 Agent 状态，体现的不是某个具体产品，而是“需要统一观察面板”这一需求。
- 这部分最稳定的可复用结论，不是具体工具名单，而是三类工作空间诉求：快速切换、跨环境执行、统一状态观察。

### 方法论演进

- 原文把 `Prompt Engineering -> Context Engineering -> Spec-driven Development -> Harness Engineering` 视为一条递进链，但同时明确这不是严格时间线，更多是问题分层。
- `Prompt Engineering`：关注如何写指令。
- `Context Engineering`：关注 Agent 每次推理时到底看到了什么。
- `Spec-driven Development`：先写清契约和验收标准，再让 Agent 执行。
- `Harness Engineering`：把架构规则、反馈回路和清理机制工程化，避免 AI 产出的熵持续累积。

### Agent 学习闭环

- 文章提出“让 Agent 替我学习”，将个人知识工作拆为采集、提炼、应用三层。
- 作者给出了一个技能栈示例：新闻聚合、播客转录、网页采集、深度研究、最佳实践提炼、工作空间演进、文档生成、工具生成、测试生成等。
- 这套闭环并不等于完全放手，作者强调的是“我只看精华版并做必要反馈和记录”，即人仍然保留筛选与纠偏角色。

### 反思与证据边界

- 原文后半段的高复用判断之一，是用 `Jagged Intelligence` 解释为什么“持续与 AI 交流”能帮助人建立边界直觉；这更像协作心智模型，而不是工程流程本身。
- “用最好的模型 + 持续与 AI 交流”在文中被作为入门启发式，而不是严格验证过的普适原则。
- 关于早期 AI 编程可能降低效率、海外使用门槛高等判断，原文主要是个人回顾与对外部材料的转述，适合保留为时代背景，不宜直接当作通用定律。

## 纵向线索

- 文章把过去一年的方法演进描述为一条连续路径：从 `Prompt Engineering` 走向 `Context Engineering`、`Spec-driven Development`、`Harness Engineering`，最后进一步走到“让 Agent 替我学习”的闭环。
- 工具层也呈现类似演化：关注点从单点提效工具，转向多 Agent、多终端、多机器协作时的统一观察、切换成本与状态管理。
- `Cockpit` 这类自研监控面板的出现，说明需求已经从“调用模型”演进到“编排和观察 Agent 系统”。
- 文章后半段则把方法论回收为协作心态：面对锯齿状能力分布，人需要通过持续交互建立直觉，而不是假定模型能力是连续稳定的。

## 横向线索

- 文章把 `Prompt Engineering`、`Context Engineering`、`Spec-driven Development` 和 `Harness Engineering` 放在同一坐标里，适合后续整理为方法路线的横向对照。
- 工具层同时出现 `Raycast`、`AeroSpace`、`Ghostty`、`tmux`、`Claude Code` 和 `Cockpit`，适合后续按“工作空间 / 执行工具 / 观察面板”做生态位拆分。
- 文中提到 OpenAI、Anthropic、GitHub Spec Kit、METR 等外部参照，说明这套工作流方法并非孤立经验，后续可沿这些线索继续补横向对比材料。
- `Jagged Intelligence` 把工程方法之外的协作心智补进来了，后续如果继续摄入 Karpathy 或类似材料，可以和 `Context / Spec / Harness` 形成“能力边界为何需要外部结构”的横向解释。
