这是一篇围绕 Memory 生命周期维护的工程笔记。它最有长期价值的判断不是某个 SQLite 方案，而是把“记忆不是搜索问题”进一步落到操作层：真正的难点在于衰减、矛盾处理、置信度、压缩和过期，而不是单纯把内容存进去再检索出来。

## 这份资料是什么

- 资料来自 Towards Data Science 文章摘录，作者在纯文本 SQLite 记忆方案基础上继续补生命周期管理。
- 文章给出了较具体的 Python 实现思路，包括衰减、矛盾检测、压缩和过期。
- 它更像一套单作者工程实践，而非跨系统基准结论。

## 主要观点

1. 会“记住一切”的系统更像档案库而不是 Memory；真正的问题常常不是记不住，而是不会让旧信息退场。
2. 记忆系统应显式维护生命周期状态，如衰减分数、过期时间、冲突替代关系和事件日志。
3. 矛盾检测与置信度评分，是把“历史条目”升级为“可治理状态对象”的关键部件。
4. 维护任务应异步后台运行，否则写入路径会被生命周期治理拖慢。

## 关键内容

### 生命周期字段

- 文中的 SQLite schema 不只存 `content / summary / tags`，还加入 `confidence`、`decay_score`、`status`、`contradicted_by`、`expires_at` 等字段。
- 这些字段的意义不在于数据库设计技巧，而在于它们把“这条记忆现在还健康吗”变成了系统可回答的问题。

### 衰减、矛盾与压缩

- 衰减让长期不再被访问的记忆逐步降权并归档，而不是永久与新记忆同权。
- 矛盾检测让新事实可以取代旧事实，同时保留可追溯关系。
- 压缩把重复或碎片化记忆合并成更稳定的上层表示，避免无限堆积。

### 证据边界

- 文章使用 plain-text SQLite 和记忆索引作为样例路线，并不代表这比 embedding / graph / hybrid storage 普遍更优。
- 值得保留的是其生命周期治理语言，而不是具体技术栈。
