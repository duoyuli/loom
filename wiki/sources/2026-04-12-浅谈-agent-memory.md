lencx 发布于微信公众号"浮之静"的一篇综述性文章，系统梳理 Agent Memory 的认知科学根基、生命周期机制、架构哲学与治理难题。核心主张是：Memory 从来不是存储或检索问题，而是"治理过去如何进入现在"的状态管理问题。

## 主要观点

**核心定位：Memory 的边界**

- 没有 Memory 的 Agent 永远从第一天开始；Memory 是 Agent 从"一次性工具"转向"长期协作者"的分水岭。
- Memory 真正处理的，是系统如何在时间中维持连续性、更新自我理解、并且不被自己的过去拖死。核心不是"把过去留下来"，而是**治理过去如何进入现在**。

**认知科学根基：CoALA 四类记忆**

CoALA（Cognitive Architectures for Language Agents）借用经典认知架构，把 Agent 记忆划分为四类：

- **工作记忆**：当前可直接参与推理的上下文；所有记忆必须通过的瓶颈。
- **情景记忆**：带时间属性的经历记录（一次对话、工具调用轨迹）。Generative Agents 以"近因性×重要性×相关性"加权检索，并在重要性积累到阈值时触发反思，把离散经历提炼为高阶理解。
- **语义记忆**：从大量经历中蒸馏的稳定知识（偏好、实体关系、长期约束）；比情景记忆紧凑但失去原始语境。HippoRAG 以知识图谱+图传播模拟这一迁移过程。
- **程序性记忆**：规则内化为行动模式的层，对应 Agent 里的 Skills/SOP。最容易被低估。

四类记忆不是标签，而是四种不同的时间残留物；它们共同回答"经历是否能被转化、转化是否还能回溯、回溯之后又能否重新进入行动"。

**RAG ≠ Memory**

- RAG 解决的是"模型不知道，但资料库里有"——访问静态知识，主要体现为"读"。
- Memory 覆盖写入、更新、替代、失效、删除的完整生命周期；处理的是互动中形成的偏好、事实变化、错误教训如何持续影响未来行为。
- Letta（原 MemGPT）明确主张"RAG is not Agent Memory"；把 Memory 误解为"更聪明的检索"会导致架构从根上做偏。
- RAG 和 Memory 的差别不是实现技巧的差别，而是一个系统**有没有开始拥有历史**的差别。

**Memory 生命周期：写入 → 整理 → 读取**

Memory 是一条有损重建管线，每个阶段都造成信息损失、语义偏移和选择性偏见：

- **写入**：提取候选记忆 → 写入门控（过滤噪声/低价值信息）→ 元数据标注（类型、来源、时间、置信度）。Memory 第一道败局通常不是读错，而是写脏。
- **整理**：合并去重、冲突调解、版本替换、衰减归档、标记失效。成熟系统把记忆视为有生命周期的状态对象，而不是永远平铺的文本条目。真正难的是**让旧版本以正确的方式退场**。
- **读取**：混合召回 → 重排序 → 过滤 → 预算裁剪 → 上下文组装。系统不是在"还原过去"，而是在"为当前任务重构一个可行动的过去版本"。

**"破电话"效应：原始 vs 派生**

- **原始材料（Raw）**：保真，但太散、太碎、注入成本高；大上下文窗口不是解法，只是把这条路推到极致。
- **派生材料（Derived）**：紧凑可用（摘要、画像、偏好标签），但已经是"系统认为发生了什么"，而非"发生了什么"；派生继续喂养派生，会导致系统性漂移。
- 真正严重的风险：记错了还以为自己记得很清楚，比"记不住"更致命。
- 严肃的记忆系统必须**同时持有原始和派生，并维持可回溯、可校验、可重构的路径**；没有证据层，系统会漂；没有派生层，系统会钝。

**遗忘的重要性**

- "Forget ≠ Delete"：删除原始消息不等于删除摘要，删除摘要不等于删除由此提取的偏好。遗忘是**谱系清算**——追溯这条信息去过哪里、影响过哪些派生物。
- 好的 Memory 不是"永不遗忘"，而是具备高质量遗忘能力：让失效的东西退场，让历史可以被审计，但不再统治现在。
- 真正成熟的遗忘机制：带版本意识、时间意识和依赖传播意识的退场机制；管理的不是消失，而是**失效之后仍可追溯、但不再继续支配当前行为**。

**Skills：程序性记忆的外化**

- Skills 是程序性记忆的外化形式，代表记忆从"保存过去"走向"塑造未来行为"的成熟产物。
- 学术脉络：Reflexion、ExpeL、ReMe 都在回答同一问题：经历如何不只是被保存，而是被提炼成下一次行动时可直接调用的能力。
- 高质量程序性记忆在某些场景下可以部分替代模型规模本身的不足。
- Memory 的终点不是档案，而是能力：经验 → 总结过 → 会做了。

**MemGPT：操作系统隐喻**

- 把 LLM 上下文窗口视为 RAM，外部存储视为磁盘；Memory 不是"怎么检索"，而是"如何在有限工作区和外部长时存储之间建立有效调度"。
- 上下文窗口只是展示面；真正的 Memory 是后台的调度能力。
- 把记忆从内容问题重新改写为**资源问题**：过去何时被调入、以什么形态调入、又何时被换出。

**五种架构哲学**

1. **文件驱动**：可见、可编辑、可审计；强调透明性，但不天然擅长自动演化。
2. **图谱驱动**：组织实体、关系、状态变化和时间有效性；擅长处理同一对象在不同时期状态不同的问题；实现复杂度高。
3. **混合存储驱动**：向量、图、KV 等联合承载，分工处理召回、关系推理、时间变化和快速注入。
4. **策略学习驱动**：让系统直接学习记忆管理策略（何时记、记什么、何时忘、如何改写）；手工启发式规则被可学习策略替代。
5. **技能蒸馏驱动**：以可复用能力为终点；上限最高也最危险——蒸馏出错则固化的是高效率重复错误。

**治理层**

- 治理层管理：来源（原话/摘要/推断）、权限、生命周期、置信度、影响范围、可撤销性。
- 没有治理层的 Memory 容易从"连续性来源"变成"污染源"——混淆原话和推断、历史事实和当前状态、私人上下文和可跨任务携出的知识。
- Memory 更像操作系统（调度、隔离、继承、回收、审计、控制），而不是数据库（数据在不在）。

**多 Agent 记忆共享**

- 问题不是"大家共用一个库"，而是一套社会性安排：谁拥有经验、谁拥有解释权、谁对哪部分过去负责。
- 三大难点：边界不清则互相污染；追溯不清则错误失去责任主体；一致性崩坏则只剩彼此冲突的叙事碎片。

**评估**

好的评估不只测"能否想起"，还要测：能否记对、记稳、有边界地记、并且在该忘的时候忘掉；能否区分"曾经成立"与"现在仍然成立"；在多次摘要后是否逐渐漂移。
